MiniCodeAI 代码智能体 Agent 开发项目

1. 引言
   1.1 项目背景
   随着软件开发规模的扩大，开发者需要频繁查阅文档、理解代码逻辑、排查技术问题。传统搜索引擎返回的链接需要手动筛选，效率低下；而通用大模型缺乏针对特定代码库的上下文，易产生幻觉且无法溯源。因此，本项目旨在构建一个面向开发者的多模态 RAG 智能体，能够理解代码、技术文档、设计稿等多种输入，通过对话式交互为开发者提供精准、可溯源的问答和代码辅助服务。

1.2 项目目标
主要目标：搭建一个可落地的 Agent 系统，支持多格式文档（PDF、图片、Markdown等）的解析、混合检索与智能问答，并提供流式对话界面。

性能目标：检索 Top-5 准确率 ≥ 85%，平均响应时间 ≤ 3s，答案幻觉率（Faithfulness）≤ 0.2。

工程目标：模块化设计，支持增量索引、易扩展新工具，并提供 Docker 一键部署方案。

1.3 范围
本项目包含以下核心模块：

文档解析与索引子系统：支持多种文档格式解析，构建向量+BM25 混合索引。

智能体调度子系统：基于 LangChain 构建 Agent，集成工具调用、记忆持久化、人工干预。

检索增强生成（RAG）子系统：包含查询改写、多路召回、Rerank、引文校验。

API 与前端交互子系统：提供 RESTful API 和基于 SSE 的流式对话页面。

评测与运维子系统：RAGAS 自动化评测、Docker 部署、日志与监控。

不在范围内：本版本不涉及多租户管理、复杂权限体系（如 RBAC）、大规模分布式部署（单机 Docker 足够）。

1.4 术语与缩略语
术语 定义
RAG Retrieval-Augmented Generation，检索增强生成
Agent 智能体，能够自主规划、调用工具完成任务的程序
LLM 大语言模型，本项目使用 DeepSeek-V3/R1
VLM 视觉-语言模型，用于生成图像语义描述
BM25 一种经典的文本相关性评分算法，用于全文检索
Rerank 重排序，对候选文档块进行二次相关性打分
SSE Server-Sent Events，服务端推送技术，用于流式输出
MCP Model Context Protocol，模型上下文协议，用于标准化工具接口
RAGAS 专用于 RAG 系统的量化评测框架 2. 总体描述
2.1 用户角色
角色 描述
普通开发者 上传文档、提问、查看答案与引用来源，可与 Agent 多轮对话
管理员（可选） 管理知识库（增删文档）、查看系统日志、调整检索参数（本版简化）
2.2 产品视角
该系统是一个面向开发者的本地化智能助手，所有数据存储在用户可控的环境中（离线部署），确保隐私与数据安全。前端为单页应用，后端提供 API，两者通过 HTTP/SSE 通信。

2.3 假设与依赖
假设：用户具备基础的计算机操作能力，文档编码为 UTF-8。

依赖：

DeepSeek API 或本地部署模型（需稳定连接）

Chroma 向量库运行正常

Redis 服务可用（用于缓存）

Docker 环境（用于一键部署）

3. 功能需求
   3.1 文档管理
   编号 功能 描述 优先级
   FR-1 文档上传 支持拖拽或点击上传 PDF、PNG/JPG、Markdown、TXT 格式，单文件 ≤ 50MB。异步解析，返回任务 ID。 高
   FR-2 文档解析 PDF 提取文本、表格、图片位置；图片调用 OCR 和 VLM 生成语义描述。文本按段落、标题切分块（chunk size 可配置）。 高
   FR-3 增量索引 新文档上传后自动更新向量库和 BM25 索引；删除文档时同步移除其所有块。 高
   FR-4 文档列表 展示已上传文档名称、大小、上传时间，支持删除操作。 中
   FR-5 文档预览（可选） 支持查看原始文档内容（仅文本）。 低
   3.2 检索与问答
   编号 功能 描述 优先级
   FR-6 自然语言对话 支持多轮对话，Agent 能理解上下文并给出连贯回答。 高
   FR-7 混合检索 同时使用向量检索（语义）和 BM25（关键词），合并候选集。 高
   FR-8 查询改写 将用户问题扩展为 3 个同义查询，提高召回率。 高
   FR-9 重排序（Rerank） 使用专用模型对候选块精排，返回 Top-5 最相关块。 高
   FR-10 引文校验 若 Top-5 块与问题相关性低于阈值，提示“无法可靠回答”。 高
   FR-11 引用展示 回答中标注引用来源（文件名、页码），前端可点击跳转。 高
   FR-12 流式输出 实时显示 Agent 思考步骤、检索过程和生成答案。 高
   FR-13 外部搜索 当本地知识库无法回答时，Agent 可调用网络搜索工具（Tavily）。 中
   3.3 智能体调度
   编号 功能 描述 优先级
   FR-14 工具调用 Agent 可调用检索工具、代码执行工具、文档摘要工具、网络搜索工具。 高
   FR-15 任务规划 Agent 根据问题自主选择工具和执行顺序（ReAct 框架）。 高
   FR-16 记忆持久化 同一会话（session_id）的对话历史存储在 Redis，支持上下文保持。 高
   FR-17 人工介入 对敏感操作（如执行代码、删除文档）需用户前端确认后才能继续。 高
   FR-18 MCP 兼容 工具接口遵循 MCP 协议，便于接入其他 Agent 生态。 低（扩展性）
   3.4 评测与监控
   编号 功能 描述 优先级
   FR-19 自动化评测 使用 RAGAS 对测试集计算 Faithfulness、Answer Relevancy、Context Relevancy。 高（内部）
   FR-20 日志记录 记录每次请求的输入、检索块、输出、耗时，便于调试。 高
   FR-21 健康检查 提供 /health 端点，检查各依赖服务状态。 中
4. 非功能需求
   4.1 性能
   并发处理：支持至少 100 个并发请求，平均响应时间 ≤ 3s（不含模型生成时间）。

吞吐量：单节点 QPS ≥ 20（查询类接口）。

资源占用：内存占用 ≤ 8GB（含向量库），CPU 使用率 ≤ 80%。

4.2 可用性
系统可用性：≥ 99.9%（部署环境稳定情况下）。

故障恢复：关键服务（Chroma、Redis）重启后系统自动重连，不影响已有会话（会话状态持久化）。

4.3 安全性
数据加密：传输层使用 HTTPS（生产环境），敏感 API Key 通过环境变量注入。

代码执行安全：代码执行工具运行在隔离的 Docker 容器中，限制系统调用和网络访问。

权限控制：暂不实现用户认证（本地部署），但提供 API 签名预留。

4.4 可扩展性
系统设计为模块化，可方便替换 LLM、嵌入模型、向量库。

新增工具只需注册到 Agent 工具箱，无需修改核心逻辑。

4.5 可维护性
代码遵循 PEP 8 规范，提供详细的函数注释。

使用 Docker Compose 编排所有服务，环境一致性高。

提供一键部署脚本（./deploy.sh）和回滚方案。

4.6 兼容性
前端支持 Chrome 90+、Firefox 88+、Edge 90+。

后端支持 Python 3.10+，依赖包版本锁定。

5. 外部接口需求
   5.1 用户界面
   Web 单页应用，采用 Vue3，响应式设计，适配桌面与平板。

布局：左侧对话区（流式渲染 Markdown）、右侧文档管理面板。

交互：文件拖拽上传、对话输入框、人工介入确认按钮。

5.2 软件接口
LLM API：调用 DeepSeek HTTP API（或 OpenAI 兼容接口），超时设置 60s。

VLM API：调用 Qwen-VL HTTP API，用于图片描述。

向量库：Chroma 通过 HTTP 或本地文件持久化。

缓存：Redis 通过 TCP 连接。

网络搜索：Tavily Search API（需 API Key）。

5.3 通信协议
后端对外提供 RESTful API（JSON 格式）。

流式输出使用 SSE（Server-Sent Events）协议。

内部模块间采用异步方法调用，无额外 RPC。

6.2 存储要求
向量库：Chroma 持久化到本地磁盘（./chroma_data）。

缓存库：Redis，内存型，RDB 持久化。

文件存储：原始文档保存在 ./uploads/ 目录。

日志：滚动写入 ./logs/ 目录，保留 7 天。
